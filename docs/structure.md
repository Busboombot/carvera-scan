# Repository structure

Status: done 2026-11-05 (decisions at the end). The old history is in
`~/carvera-scan-history-2026-11-05.bundle` on the Mac and on Buzzkill.

## The problem

The repo has about 200 changed or untracked files at any time, and most of them are
not worth keeping: one-off analysis scripts, plots, test runs, 60 MB viewer folders.
Code, configuration and CAD sit next to them and get lost in the noise. Some of the
things that matter live only inside `data/` today:

- the three.js viewer, `index.html`, which is copied by hand into each `view3d*/` folder
  and is not generated by any script
- the mount plate and dongle bracket CAD, in `data/2026-11-04/mount-plate/`
- the calibration files the current pipeline depends on, `zcal45deep/*.json` and
  `axis45/*/matrix.json`
- the hand-made inputs `objects.json` and `heights.json`, and the Cutebot Pro
  measurements

## Three kinds of files

Every file in this repo is one of three kinds. Its kind decides where it goes.

| Kind | What it is | Where it goes | In git? |
|---|---|---|---|
| **Kept** | Code, config, calibration sets, CAD sources, docs, small text results we cite | `src/`, `projects/`, `config/`, `design/`, `docs/`, `tests/` | yes |
| **Data** | Raw captures from the machine. Big, and only replaceable by running the machine again | `data/<date>/<capture>/` | no; backed up to Buzzkill |
| **Scratch** | Anything made while working: test scripts, plots, products of trial runs, notes for this session | `scratch/` | no; delete when you like |

If you're unsure, it goes in `scratch/`. Moving something out of `scratch/` into a kept
directory is a deliberate step, done when we decide to keep it.

**No images in git.** Plots, renders, schematics and photos are things an agent makes
to look at results. They are rebuilt from code and data, so they go in `scratch/` or a
project's `out/`. `.gitignore` ignores image files everywhere. An image that has to be
kept needs its own exception line in `.gitignore`, with a comment saying why.

## Layout

```
carvera-scan/
  README.md               what this is, the layout, how to run a scan
  AGENTS.md               rules for agents: where files go, machine safety
  pyproject.toml  uv.lock
  .gitignore

  src/
    carvera_scan/         the Python package (import carvera_scan)
      machine.py          Carvera client through cmux: limit-checked moves, light
      arducam.py          the cameras (V4L2 MJPG, by USB port)
      calib.py            calibration sets: build and load config/calib/*.json
      acquire/            runs on kinsey: line_scan, z_sweep, survey, axis_test, probe_z, look
      process/            frames -> points -> grid: cross, line_height, sweep_height,
                          zcal, grid, clean, blocks_merge, stereo; pipeline (the
                          standard chain) and bench (its regression test)
      measure/            flatness, heights_report, probe_compare, edge_lengths, shapes
      view/               view3d (writes the data files the viewer loads)
    hosts/                code and setup that belong to one machine
      kinsey/             cmux.py (runs on system python3), systemd/, udev/, deploy.sh
      buzzkill/           push.sh (Mac -> Buzzkill code), README (venv, install)

  projects/               one directory per thing we scan or show
    viewer/               the three.js viewer page; view3d copies it into each build
    blocks-123/           the 1-2-3 block accuracy test
    sheet-flatness/       the aluminium sheet against the probe
    cutebot-pro/          Cutebot Pro mounting points and clearances for a printed shell
    plate-model/          the mount plate scanned and fitted into an OpenSCAD model

  design/                 parts we made for the machine
    camera-mount/         the two-camera + line laser bracket: requirements
                          (from docs/camera-mount-geometry.md), and CAD when it exists
    mount-plate/          plate and the USB-to-vacuum dongle bracket (*.scad)

  config/
    calib/<name>.json     calibration sets (carvera_scan.calib), README lists them
    dev/ prod/ local/     dotconfig env layers (unchanged)
    dotconfig.yaml  sops.yaml  AGENTS.md

  docs/
    structure.md          this file
    package-plan.md       design and plan for the package
    hardware.md           the machine, cameras, laser, G-codes we use (from README)
    log.md                the lab notebook (the dated log, from README)

  tests/                  unit and regression tests; small fixtures in tests/data/

  data/                   IGNORED. Raw captures, data/<date>/<capture>/
  scratch/                IGNORED. Working files; see below
```

There is no `attic/` and no `examples/`. Code we will use again is in the package;
code we won't is deleted. It can still be recovered from the history bundle (step 2 of
"Doing the move").

### `src/carvera_scan/`

The package. All reusable code goes here, and nothing else does. Modules import each
other as `carvera_scan.process.cross` and so on, not by bare file name. Each script
keeps its command line, run as `python -m carvera_scan.process.cross …`. The `cscan`
command and the deeper split in `docs/package-plan.md` §5.1 (`calib/`, `export/`,
`safety.py`, the simulator) come in Phase 2. This move does not refactor anything.

The package has to stay importable on kinsey, which has only numpy and OpenCV. So
`machine.py`, `arducam.py` and `acquire/` must not import anything from `process/`,
`measure/` or `view/`.

Two files come in from outside the current pipeline:

- **`process/stereo.py`**, from `attic/analysis/stereo_sweep.py`: two-camera stereo
  from two `line_scan` sweeps. The new camera mount is designed so that stereo works
  (`design/camera-mount/`), and this is the code that will use it.
- **`measure/shapes.py`**, from `examples/…/fit_shapes.py`: shape fitting and the
  photo mosaic (`Mosaic`, `level`). Both the Cutebot and the plate-model projects use
  it.

### `src/hosts/<machine>/`

Code that runs on one machine only, or that sets that machine up. kinsey gets `cmux.py`
(a standalone service on system `python3`), the systemd units, the udev rule and
`deploy.sh`. `deploy.sh` then copies `src/carvera_scan` and `src/hosts/kinsey` to
`kinsey:~/carvera-scan`. Buzzkill gets its setup and sync scripts. What has been done to
a machine is still recorded in busboom-home-network `hosts/<name>/README.md`, not here.

### `projects/<name>/`

A project is one thing we scan, measure or show. It holds:

- `README.md`: what it is, the commands that produce it, and the results we cite
- the project's own scripts, when they are specific to it (the Cutebot feature finder,
  the plate CAD writer). Anything reusable goes in the package instead.
- its hand-made inputs, such as `objects.json`
- `results/`: small text results worth keeping, such as `heights.json` and
  `features.json`. No images.
- `out/`: IGNORED. Everything generated: point clouds, PLY files, viewer data,
  `ortho.png`, schematics, `.scad`/`.stl` written by scripts. These can be rebuilt
  from `data/` and the code.

To look at a project, serve its viewer build over a local HTTP server, e.g.
`python3 -m http.server 8000 -d projects/blocks-123/out/view3d`.

`projects/viewer/` is a project too: the three.js page that shows the outputs. It is
the one checked-in copy; `carvera_scan.view.view3d` copies it next to the data it
writes, so each build is a self-contained folder.

### `design/`

Physical parts for the machine: hand-written OpenSCAD sources and requirement notes.
Renders and STL files are generated from the `.scad`, so they are ignored.

### `config/`

Configuration that is checked in. Calibration sets are `config/calib/<name>.json`, built
by `python -m carvera_scan.calib build`; each names the captures it came from, and
`config/calib/README.md` lists them. The captures themselves stay in `data/`. A
`rig.yaml` (package-plan §5.3) comes with the `cscan` command in Phase 2.

### `data/`

Raw captures only: frames, `scan.json`, `moves.json`, `stops.json`, probe logs. One
folder per capture, under the date. It is ignored as a whole, so we don't have to keep
rules about which file types inside it to track. Products don't go here; they go in
`projects/<name>/out/` or `scratch/`. The master copy is on whichever machine took the
capture (kinsey), with the full set on Buzzkill at `~/carvera-scan/data/`.

### `scratch/`

Everything else. Agents put session work here without asking:

```
scratch/<date>-<topic>/   e.g. scratch/2026-11-05-arm-bias/
```

A folder holds that session's throwaway scripts, plots, trial products and notes. Bench
runs (`bench/r0_baseline/` …) and their cache go to `scratch/bench/`. Nothing in
`src/` or `projects/` may read from `scratch/`. If a script turns out to be worth
keeping, it moves into `src/` (code) or `projects/` (a project's recipe).

## `.gitignore`

See the file. It ignores `/data/`, `/scratch/` and `/projects/*/out/`; every image,
STL, `.npz`, `.npy` and `.ply` anywhere (to keep one, add a `!path` line with a reason);
and the usual Python and tool caches. The old `data/.gitignore` is gone.

## Rules for agents (in `AGENTS.md`)

1. Working files go in `scratch/<date>-<topic>/`. That includes every plot and image.
   Don't put them anywhere else, and don't ask first.
2. Don't add files to `src/`, `projects/`, `config/`, `design/` or `docs/` unless they
   are meant to be kept. Edit what is there instead.
3. Captures go in `data/<date>/<capture>/`. Never write products into `data/`.
4. Processing runs on Buzzkill (`~/carvera-scan`), capture on kinsey; the Mac edits
   and views.
5. Machine safety rules: from `docs/hardware.md` and the current README. They include
   no motion without Eric's go-ahead and probing only with firmware commands.
6. `git status` should be short. If it lists more than a handful of files, something
   is in the wrong place.

## How the move was done (2026-11-05)

1. **Backup:** a snapshot commit of the whole tree except `data/` on the local branch
   `pre-reorg-snapshot`, then `git bundle create ~/carvera-scan-history-2026-11-05.bundle
   --all`, copied to Buzzkill. The old commits, the attic scripts and the tracked
   2026-11-01 images can be restored from it (`git clone <bundle>`).
2. **Move** with the table above; bare-module imports became package imports
   (`from carvera_scan.process import cross`), the `sys.path` hacks went, and the
   command lines in docstrings became `python -m carvera_scan.…`.
3. **Checks:**
   - Mac: `uv sync`, `uv run pytest` (every module imports; the capture side imports
     nothing from `process/`, `measure/`, `view/`, scipy or Open3D).
   - kinsey: the capture modules import with its own venv (Python 3.12), from a temp
     copy.
   - Buzzkill: the bench on the new layout matches s7 on every metric, and the viewer
     build is byte-identical to one made before the move (all data files).
   - `deploy.sh -n`: only the package is new; `cmux.py` is unchanged.
4. **One commit** on a fresh history, pushed to GitHub.

## Decisions (Eric, 2026-11-05)

1. **attic/:** code we'll use again goes into the package; the rest is deleted. Only the
   two-camera stereo sweep is kept, as `process/stereo.py`. The webcam, dot-laser,
   ChArUco, motion-stereo and magnification code goes.
2. **Images:** none are kept in git. They go in `scratch/` or `out/`, and `.gitignore`
   ignores them everywhere.
3. **Cutebot Pro:** it is a project, `projects/cutebot-pro/`, including its doc and
   outline from `docs/`.
